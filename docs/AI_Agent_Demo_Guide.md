# 🤖 Руководство по интеграции ИИ-агентов и MCP (AI-Driven QA Guide)

В данном документе описана архитектура и практический процесс использования ИИ-агентов (Zoo-code / Cline) в роли автономных QA-инженеров для тестирования **Системы Обработки Учебной Информации (СОУИ)**. 

Главная инновация проекта — использование протокола **Model Context Protocol (MCP)**, который дает ИИ-агенту "глаза и руки" для прямой работы с инфраструктурой, превращая его из обычного чат-бота в полноценного участника процесса тестирования (Data-Driven Testing).

---

## 🛠️ 1. Интеграция Model Context Protocol (MCP)

ИИ-агент взаимодействует с базой данных через выделенный локальный MCP-сервер.

* **Конфигурация (`mcp/cline_mcp_settings.json`):** Агент использует официальный сервер `@modelcontextprotocol/server-postgres` для подключения к Docker-контейнеру с БД.
* **Возможности агента через MCP:**
  * Прямая инспекция DDL-схемы PostgreSQL 16 (таблицы, связи, типы данных).
  * Выполнение read-only SQL-запросов для сверки (reconciliation) данных API и БД.
  * Валидация сложных ограничений: `FOREIGN KEY`, `ON DELETE RESTRICT` и `CHECK`-ограничений.

---

## 📋 2. Архитектура системных промптов (System Instructions)

Агент не генерирует тесты хаотично. Его поведение строго регламентировано через Role-based промпты, хранящиеся в директории [`.agent/prompts/`](../.agent/prompts/). Промпты включают жесткие правила форматирования, плейсхолдеры и запреты на "галлюцинации" ссылок.

1. [`01_test_designer.prompt.md`](../.agent/prompts/01_test_designer.prompt.md) — Проектирование тест-кейсов и матрицы покрытия.
2. [`02_crud_testing.prompt.md`](../.agent/prompts/02_crud_testing.prompt.md) — Сквозное тестирование CRUD-операций REST API.
3. [`03_field_validation.prompt.md`](../.agent/prompts/03_field_validation.prompt.md) — Анализ граничных значений (BVA) и валидация полей ввода (например, поиск обхода ограничений вроде `CHECK grade < 0 or > 60`). Вывод строго в Markdown-таблицах.
4. [`04_reports_testing.prompt.md`](../.agent/prompts/04_reports_testing.prompt.md) — Сверка данных (Reconciliation): агент сверяет ответ API с результатами прямых SQL-запросов.
5. [`05_bug_reporter.prompt.md`](../.agent/prompts/05_bug_reporter.prompt.md) — Стандартизированная генерация баг-репортов (формат Jira). Включает строгие правила Markdown (запрет на абсолютные пути и номера строк в ссылках).

## 🔄 3. Воркфлоу AI-Assisted QA

Процесс работы построен в виде непрерывного цикла валидации:

1. **Развертывание окружения:** Запуск FastAPI и PostgreSQL через Docker Compose ([`docker-compose.yml`](../docker/docker-compose.yml)).
2. **Базовый прогон (Smoke):** Выполнение API-автотестов через Postman/Newman ([`tests/soui_postman_collection.json`](../tests/soui_postman_collection.json)).
3. **AI-Инспекция (Deep Dive):** Агент подключается к БД через MCP, читает схему и ищет расхождения (Requirement Mismatch) между архитектурой и бизнес-логикой.
4. **Синтез дефектов:** Автоматическая генерация формализованных отчетов о найденных уязвимостях.
