# Отчет об ошибке: BUG-005

- **Title (Заголовок):** [API] Вводящее в заблуждение сообщение об ошибке при нарушении внешнего ключа (FK) в эндпоинте `POST /api/v1/journal` в [app/main.py](../../app/main.py)
- **Severity / Priority:** Major / Medium (Затрудняет отладку и интеграцию, возвращая пользователю неверную причину ошибки)
- **Environment:** Docker Compose, FastAPI, PostgreSQL 16
- **Preconditions (Предусловия):** База данных развернута и инициализирована через [docker-compose.yml](../../docker/docker-compose.yml).
- **Steps to Reproduce (Шаги для воспроизведения):**
  1. Выполнить HTTP-запрос POST на создание записи в журнале с несуществующим `teacher_id` (например, `9999`):
     ```bash
     curl -s -X POST "http://localhost:8000/api/v1/journal" -H "Content-Type: application/json" -d '{"teacher_id": 9999, "student_id": 1, "control_point_id": 1, "assignment_id": 1, "grade": 50, "submission_date": "2026-05-15"}'
     ```
  2. Проверить тело ответа и код состояния HTTP.
- **Actual Result (Фактический результат):**
  - Возвращается код состояния `400 Bad Request` с телом ответа:
    ```json
    {"detail":"Ошибка внешнего ключа или ограничений: шкала оценок строго 0-60"}
    ```
  - Запись в журнале не создается.
- **Expected Result (Ожидаемый результат):**
  - Возвращается понятное сообщение об ошибке, указывающее на то, что преподаватель с указанным ID не существует (нарушение внешнего ключа), а не на то, что оценка должна быть строго 0-60 (так как оценка `50` абсолютно валидна).
- **Root Cause Analysis (Предполагаемая причина):**
  - В файле [app/main.py](../../app/main.py) в эндпоинте `POST /api/v1/journal` блок `except IntegrityError` перехватывает абсолютно любые ошибки целостности (включая нарушение внешних ключей `teacher_id`, `student_id`, `control_point_id`, `assignment_id`) и жестко возвращает сообщение `"Ошибка внешнего ключа или ограничений: шкала оценок строго 0-60"`, что вводит пользователя в заблуждение.
