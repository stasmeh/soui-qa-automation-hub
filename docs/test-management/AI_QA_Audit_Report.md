## 3. Аудит ограничений схемы и валидации полей (`03_field_validation.prompt.md`)

Инспекция схемы [`student`](docker/init-db/01_schema.sql) выявила жесткие ограничения (`CHECK constraints`):
- Поля `last_name`, `first_name`, `middle_name` проверяются регулярным выражением `~ '^[А-Яа-яЁё]+$'`.
- **Выявленный дефект UX/Логики:** Регулярное выражение строго требует слитного написания только кириллических букв без учета пробелов и дефисов (например, фамилии двойные вроде «Иванов-Петров» или отчества/имена с пробелами вызывают ошибку валидации). Данный кейс зафиксирован как дефект.

## 4. Выполнение отчетных SQL-запросов и бизнес-логики (`04_reports_testing.prompt.md`)

Выполнен тестовый отчетный запрос по группе `ИВТ-21` и предмету `Базы данных`:
```sql
SELECT 
    sg.group_code AS "Группа",
    sub.name AS "Предмет",
    CONCAT(s.last_name, ' ', s.first_name) AS "Студент",
    j.grade AS "Оценка (0-60)",
    j.submission_date AS "Дата сдачи"
FROM journal j
JOIN student s ON j.student_id = s.student_id
JOIN student_group sg ON s.group_id = sg.group_id
JOIN assignment a ON j.assignment_id = a.assignment_id
JOIN subject sub ON a.subject_id = sub.subject_id;
```
**Фактический результат из БД [`soui_db`](docker/docker-compose.yml:8):**
| Группа | Предмет | Студент | Оценка (0-60) | Дата сдачи |
|---|---|---|---|---|
| ИВТ-21 | Базы данных | Иванов Иван | 55 | 2026-05-15 |

## 5. Оформление баг-репорта (`05_bug_reporter.prompt.md`)

### BUG-002: Ограничение CHECK для ФИО не поддерживает дефисы и составные имена
- **Приоритет:** Medium / High
- **Компонент:** База данных / Схема `student`
- **Описание:** Регулярное выражение `CHECK (last_name::text ~ '^[А-Яа-яЁё]+$'::text)` блокирует добавление реальных фамилий с дефисами (например, *Римский-Корсаков* или *Петрова-Водкина*).
- **Шаги воспроизведения:** Выполнить вставку записи с дефисом в `last_name`.
- **Ожидаемый результат:** Корректная обработка составных фамилий.
- **Фактический результат:** Ошибка нарушения `CHECK constraint`.
