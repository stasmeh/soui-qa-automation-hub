# 📋 QA Checklist & Test Coverage

анный чек-лист представляет собой высокоуровневую выжимку из **80+ детальных тест-кейсов**, спроектированных для приложения СОУИ. 
*Примечание: Так как данный репозиторий представляет собой Backend-часть системы, чисто интерфейсные проверки вынесены за рамки скоупа.*

**Легенда статусов:**
* 🤖 **API** — Покрыто автотестами (Postman / Newman / Pytest)
* 🗄️ **DB** — Покрыто SQL-скриптами или констрейнтами СУБД (PostgreSQL)
* 🧠 **AI** — Проанализировано/Сгенерировано ИИ-агентом через MCP
* 🚫 **UI** — Out of Scope (Проверки на стороне будущего клиентского интерфейса)

---

## 1. 🗂 Модуль «Справочники» (Dictionaries & Master Data)
*Охватывает сущности: Специальность, Группа, Студент, Преподаватель, Предмет, Задание, Контрольная точка.*

- [x] **CRUD-операции:** Успешное создание, редактирование и удаление записей с валидными данными. (🤖 **API** / 🧠 **AI**)
- [x] **Required Fields:** Система выдает ошибку (422/400) при попытке сохранения сущности без обязательных полей. (🤖 **API**)
- [x] **Regex Validation:** Блокировка ввода латиницы и спецсимволов в кириллических полях (ФИО, названия специальностей). (🗄️ **DB Check**)
- [x] **BVA & Type Validation:** Блокировка отрицательных значений и нуля (например, часы предмета), ввода текста в числовые поля. (🗄️ **DB Check** / 🧠 **AI**)
- [x] **Уникальность (Unique):** Запрет создания дубликатов для кодов и шифров. (🗄️ **DB Constraint**)
- [x] **Ссылочная целостность (Foreign Key):** Запрет удаления родительской записи, если на нее есть ссылки. (🗄️ **DB Restrict**)
- [x] **Сортировка:** Корректная сортировка списков (по алфавиту, по группе). (🤖 **API**)

## 2. 📓 Модуль «Журнал успеваемости» (Journal Lifecycle)

- [x] **State Transition (Создание):** Успешная выдача задания студенту. Поля "Оценка" и "Дата сдачи" по умолчанию `null`. (🤖 **API**)
- [x] **State Transition (Фиксация):** Успешное обновление записи: выставление оценки и даты сдачи. (🤖 **API**)
- [x] **Граничные значения (BVA) оценки:** Успешное сохранение оценки в диапазоне `[1; 60]`. Отказ в сохранении для `0`, `61`, отрицательных и нечисловых значений. (🗄️ **DB Check** / 🤖 **API** / 🧠 **AI**)
- [x] **Валидация даты:** Проверка логики при попытке выставить дату сдачи из будущего времени. (🤖 **API**)
- [x] **Зависимости журнала:** Запрет удаления сущностей, если они уже фигурируют в записях журнала. (🗄️ **DB Restrict**)

## 3. 💼 Режим преподавателя «Работа» (Filtered Views)

- [x] **Контекстная фильтрация:** Эндпоинт журнала корректно возвращает массив записей, отфильтрованный по передаваемой паре `teacher_id` + `subject_id`. (🤖 **API**)
- [x] **Обязательность параметров:** API возвращает ошибку `422/400`, если запрос на получение журнала отправлен без обязательных параметров фильтрации. (🤖 **API**)
- [ ] **Smart-создание (Клиентская логика):** При добавлении записи из отфильтрованного вида на фронтенде поля «Преподаватель» и «Предмет» предзаполняются автоматически и блокируются. (🚫 **UI**)
- [x] **Дополнительные фильтры:** Корректная работа саб-фильтров (query-параметров) по «Группе» и «КТ» при обращении к журналу. (🤖 **API**)

## 4. 📊 Модуль «Отчёты и Сводная ведомость» (Reporting & Aggregations)

- [x] **Генерация файлов:** Эндпоинт отчетов успешно формирует и отдает файл `.txt` (с правильным Content-Type) по студентам, предметам и ведомостям. (🤖 **API**)
- [x] **Фильтрация ведомости:** Данные в генерируемом отчете корректно учитывают переданные фильтры. (🤖 **API**)
- [x] **Фильтрация по датам:** Отчет включает только те сдачи, которые попадают в заданный диапазон `start_date` / `end_date`. (🤖 **API**)
- [x] **Защита дат:** Обработка некорректного интервала (start_date > end_date) — возврат ошибки валидации без падения 500 Internal Server Error. (🤖 **API**)
- [x] **Точность вычислений:** Средний балл (AVG) и количество КТ (COUNT) рассчитываются математически верно. (🗄️ **DB** / 🧠 **AI**)
